## 👨‍💻 About Me

I'm a Salesforce Developer with a Salesforce Administration background, building solutions for customer and operational workflows with **Apex, Lightning Web Components, SOQL and Flow**.

Because I've worked on both the admin and development sides of the platform, I choose the right tool for each requirement. Sometimes that's a Flow, sometimes it's Apex, depending on complexity and how maintainable the solution needs to stay over time.

- ⚡ Writing bulkified, governor-limit-safe Apex that scales with data volume
- 🧩 Building reusable Lightning Web Components on wire adapters and Lightning Data Service
- 🔁 Automating processes with record-triggered and screen Flows
- 🔌 Integrating Salesforce with external systems over REST using asynchronous Apex
- 🧪 Treating testing, security and clean deployments as part of the build

## 🧭 How I Build on Salesforce

- **Clicks before code, code when it counts:** Flow for straightforward automation, Apex when logic, volume or complexity demands it
- **Bulk-safe by default:** triggers and classes written to handle large record sets within governor limits
- **Async where it fits:** Batch, Queueable and Future Apex for large volumes and callouts
- **Reusable components:** LWCs designed to be reused across screens instead of rebuilt each time
- **Secure by design:** profiles, permission sets and sharing rules planned alongside the data model
- **Tested and versioned:** Apex test classes, Git and SFDX as part of the delivery workflow
